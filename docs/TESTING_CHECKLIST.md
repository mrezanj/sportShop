# TESTING CHECKLIST

## اصول
- تست‌ها باید قابل تکرار باشند.
- نتیجه واقعی، دستور اجرا و محیط ثبت شود.
- تست موفق در یک محیط به‌تنهایی اثبات Production readiness نیست.
- داده مشتری واقعی در تست استفاده نشود.
- هر باگ مهم باید Regression Test داشته باشد.

## ثبت اجرای تست
- تاریخ:
- Branch/Commit:
- Environment:
- Command:
- Result:
- Passed/Failed/Skipped:
- Logs/Artifact:
- محدودیت‌ها:

- [ ] API tests احراز هویت و Permission
- [ ] OTP: انقضا، تلاش ناموفق، rate limit، مصرف یک‌باره
- [ ] کنترل سن خرید مکمل
- [ ] SKU یکتا و Validation تنوع
- [ ] موجودی منفی نشود
- [ ] ورود/خروج و تأیید موجودی
- [ ] دو خرید هم‌زمان برای آخرین موجودی
- [ ] رزرو، انقضا و آزادسازی
- [ ] قیمت تغییرکرده و اخذ تأیید مجدد
- [ ] تخفیف‌های متداخل و کد تخفیف
- [ ] پرداخت موفق/ناموفق و callback تکراری
- [ ] Refund و مرجوعی
- [ ] Snapshot سفارش و فاکتور
- [ ] محاسبه آستانه ارسال/بسته‌بندی
- [ ] دسترسی به Batch/Expiration فقط نقش مجاز
- [ ] Audit log عملیات مدیریتی

## پذیرش End-to-End
- [ ] مشتری مجاز محصول را پیدا و انتخاب می‌کند.
- [ ] مشتری زیر ۱۸ سال نمی‌تواند مکمل بخرد.
- [ ] محصول ناموجود قابل سفارش نیست.
- [ ] قیمت تغییرکرده قبل از پرداخت به مشتری اعلام می‌شود.
- [ ] سفارش پرداخت‌نشده رزرو محدود و قابل آزادسازی دارد.
- [ ] پرداخت تکراری باعث دوبار ثبت پرداخت/کاهش موجودی نمی‌شود.
- [ ] سفارش تا تحویل قابل رهگیری است.
- [ ] مرجوعی پس از بررسی و دریافت کالا قابل بازپرداخت است.
- [ ] هزینه ارسال و بسته‌بندی طبق دو آستانه مستقل محاسبه می‌شود.
- [ ] فاکتور اطلاعات Snapshot صحیح دارد.
- [ ] امتیاز و انقضا مطابق قواعد تأییدشده عمل می‌کند.

## معیار پذیرش
برای هر نیازمندی در Tracker، سناریوی Given/When/Then یا چک‌لیست قابل مشاهده ثبت شود.
